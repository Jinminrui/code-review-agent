# 采用 Tool-use Agent 模式而非 Single-shot 调用

## 状态

已采纳

## 背景

LLM 审查代码有两种主要模式：

1. **Single-shot**：将所有上下文一次性发给 LLM，要求一次性返回结构化结果。
2. **Tool-use Agent**：LLM 通过多轮工具调用主动获取上下文，逐步完成审查。

## 决策

采用 Tool-use Agent 模式，LLM 通过 `file_read`、`code_search`、`file_read_diff` 等工具主动获取所需上下文。

## 原因

1. 代码审查需要跨文件上下文推理，单次输入的上下文窗口有限。
2. LLM 可以根据审查发现动态决定需要查看哪些文件，比静态上下文收集更精准。
3. 工具调用使审查过程可追溯（哪些文件被读取、搜索了什么）。
4. 支持渐进式结果输出，用户体验更好。

## 后果

- 单次审查的 LLM 调用次数增加，成本上升。
- 需要实现工具执行器和工具定义。
- 需要限制最大轮次（默认 20 轮）防止无限循环。
- 保留 single-shot 路径作为 fallback（当 provider 不支持 chat 方法时）。
