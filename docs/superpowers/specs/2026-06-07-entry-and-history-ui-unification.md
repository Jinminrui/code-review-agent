# Entry And History UI Unification

- **Status:** Active
- 日期：2026-06-07
- 目标：让启动页与历史页进入和主工作台一致的“审查编辑台”视觉体系
- 范围：`packages/review-app` 中 `review-launch-page`、`session-history-page` 及其直接依赖的展示组件

## 1. 目标

主工作台已经建立了“暖灰纸面 + 深墨文本 + 锈橙风险”的审查编辑台方向，但启动页与历史页仍停留在功能可用、风格未统一的阶段。

本次扩展只解决一个问题：让用户从进入产品、发起审查到回看历史会话的路径，拥有连续的产品体验，而不是在进入主工作台前后像切换了两套应用。

## 2. 设计方向

本次采用“前室 + 案卷架”方向：

1. 启动页是进入审查桌面前的前室。
2. 历史页是回看过往审查记录的案卷架。
3. 两页都复用现有窄侧栏外壳，保持产品稳定框架。

这不是新增视觉风格，而是把已经确认过的工作台气质向前后两个场景外扩。

## 3. 启动页

### 3.1 页面角色

启动页承担的是“建立信心并发起一次新审查”，不是简单表单提交页。

因此页面需要同时具备两种信息：

1. 左侧或上方的价值说明：告诉用户这次审查会得到什么。
2. 右侧或下方的发起卡：让用户完成仓库与分支选择。

### 3.2 布局

启动页采用双区布局：

1. `前室说明区`
   展示页面标题、简短价值说明、三条能力摘要，例如改动摘要、风险卡片、diff 验证。
2. `发起卡`
   展示仓库选择、分支选择和提交按钮。

在窄屏下可以自然降为单列。

### 3.3 视觉要求

1. 说明区不做大面积营销化 hero，而是克制的产品引导。
2. 发起卡是页面视觉焦点，材质与主工作台卡片系统一致。
3. 按钮状态需要明确体现“正在创建审查”的过程。

## 4. 历史页

### 4.1 页面角色

历史页不是链接列表，而是过往审查案卷的回看入口。

每条记录至少应帮助用户快速识别：

1. 这是哪个分支对比。
2. 当前 session 状态。
3. 变更文件数和 finding 数量。
4. 是否值得优先打开。

### 4.2 布局

历史页使用纵向卡片流，不做复杂表格。每张卡片承担一个会话摘要。

页面顶部保留标题与说明，说明“可以回看和继续验证既有审查”。

### 4.3 卡片信息层级

每张会话卡片建议包含：

1. 分支关系。
2. 状态 badge。
3. repositoryPath 或简化仓库名。
4. changedFilesCount / findingsCount / highSeverityCount。

如果未来需要更多筛选，可以在现有顶部说明区下方扩展，不在本次范围内实现。

## 5. 实现边界

本次不做：

1. 设置页重设计。
2. 历史页高级筛选和搜索。
3. 新的路由层抽象。
4. 新的数据字段扩展。

## 6. 测试要求

至少补两类测试：

1. 启动页要能断言新的页面层级文案仍存在，且提交流程不回退。
2. 历史页要能断言会话卡片显示分支关系、状态与摘要指标。
